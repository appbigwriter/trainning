Diagnostique servidor, detecção e integração

Privacidade e manutenção

Entenda e aplique

Investigue por camadas. Se a página não abre, confira processo, porta e log de inicialização. Se abre sem sessões, teste a primeira mensagem, o projeto identificado e as pastas detectadas. Se há personagem mas faltam eventos ou controles, confira integração e versão. Uma correção deve responder a uma evidência específica.

Anote sintoma, reprodução, resultado esperado, resultado observado e uma hipótese por vez. Depois de cada mudança, repita o mesmo teste. No Docker, uma pasta criada depois da inicialização pode exigir recriar o container conforme a documentação. Antes de compartilhar logs, remova caminhos privados, mensagens de clientes e segredos.

Diagnóstico no diretório do Habblaud

npm run docker:logs
# Para Claude Code:
npm run mod:status
# Para Codex:
npm run codex:status

Como interpretar

docker:logs se aplica ao caminho Docker. No caminho Node, leia o terminal onde o servidor foi iniciado. Use o comando de status da ferramenta que está investigando e retire dados privados antes de compartilhar saídas.

Exemplo fictício

O escritório abre, mas um chat novo está ausente. A pessoa envia a primeira mensagem e confere a conta antes de reinstalar a ferramenta inteira.

Sua prática

Crie uma árvore com três sintomas: página inacessível, sessão ausente e controles indisponíveis. Para cada um defina um teste e uma evidência.

Salvo neste navegador quando o armazenamento estiver disponível. Exporte uma cópia pelo caderno.
